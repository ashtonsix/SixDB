Ikea LEAD owns the complete comparison. Ashton's 23 October steer prioritises
Frame's useful strengths over winning every hot loop: compressed scans,
selective consumption and avoiding materialisation. Point work keeps separate
native controls. This is a private benchmark bridge, not a Frame interface.

The [controlled Zen 5 findings](FINDINGS.md) now establish a large clustered
COUNT win and a contiguous cold selective win, alongside strong full-SUM and
scattered-cold counterexamples. All controls and losing cells remain retained.

The [filter findings](../filter/FINDINGS.md) show useful block pruning and strong
counterexamples to universal heads; [timing-order qualification](../ORDER-AUDIT.md)
requires balanced treatment order and exact duplicate controls. The
[Zen 5 owner panel](../lifecycle/ZEN5.md) shows why ARM rankings do not establish
an x86 policy. The [memory method](../../memory-characterisation/METHOD.md#spatial-fetch-learning-lookahead-and-retention)
already supplies capability-tested cache maintenance and its interpretation
limits. Reuse those laws rather than adding a scheduler or guessing residence
from allocated bytes.

The bridge consumes the owner's actual borrowed images without retained decoder
bindings or retained decoded dictionaries, and a narrow native-FOR control.
The first panel uses default dictionary-free images: no dictionary preparation
cost is present. If dictionary images are added, the uncached operations rebuild
material per touched part within each query; the existing dictionary-cache
alternative then needs its added planes, preparation and memory priced and
conditioned too. Python owns the actual Polars calls,
single-thread setting, original logical dtypes and independent expected results.
The second source cut adds the existing `catalogue_sum/count_ge` packed-leaf
program beside the ordinary owner operations, on the same unchanged images,
with its own exact duplicate. This changes the consumer, not the codec or ISA
kernel. The first native cohort remains separately identified.
Encoding, casting, mask preparation and retained capacities are reported apart
from complete query time. A scalar crossing the bridge must be consumed; no
decode-only loop stands in for the query. SUM remains exact through u128 on the
working domain; logical-domain mapping is explicit at the consumer boundary.
The ClickBench sidecars in `columns.json` retain Int16 OS/ResolutionWidth and
Int64 EventTime/UserID/hash values. Their stored u64 working domain is the signed
value's bit representation XOR 2^63. SUM chooses its Polars accumulator from an
explicit population/value bound: small integer reductions already widen; wider
ones cast only when their ordinary accumulator cannot prove the exact law.

Compare repeated warmed work, capability-tested flushed input, and a footprint
sweep. Frame payload, descriptors and dictionary planes are named separately;
Polars buffer views must be zero-copy. Selection metadata may stay prepared,
with its bytes and construction charged separately. Flushing is conditioning,
not a reset of prefetch history. Counted image bytes are not measured DRAM
traffic; PMU sensitivity must be qualified before making a serving-level claim.
The first panel is single-core query time. That can establish a cold-query win;
it does not establish throughput under a saturated shared memory bus. Any such
claim needs a separate concurrent-load comparison and responsive traffic
counters. A cold loss is also useful evidence: the codec's CPU bill may exceed
the saving in transfers at that operating point.
`frame_capacity` includes its column object and owned vector capacities;
`native_capacity` includes its narrow vector, base/bounds and shape. The common
block-mask buffer is separate. These are isolated representation capacities,
not the benchmark process's RSS (which deliberately contains every control).

Supplied-mask SUM includes Polars gather, prepared zero-copy chunk spans and a
complete span-construction-plus-SUM arm. The first two amortise preparation;
the last charges it per request. Frame mask binding and Polars index/span
construction are also reported separately. Both block layouts select the same
original blocks; the scattered layout permutes complete blocks and records the
permutation identity. Selected row density alone does not imply skipped bytes.

Full scans and supplied original-block selections can run on the existing
owner. Predicate(A) -> selected SUM/COUNT(B) additionally needs the owner mask
emitter being implemented by Claude. Coarse selection, fine row selection,
presence and A/B validity remain distinct. Clustered/dispersed selections at
equal density must survive through actual payload consumption.

Configure the private shared bridge with the pinned compiler and
`-DSIXDB_SPIKES=frame-phase-1 -DCMAKE_POSITION_INDEPENDENT_CODE=ON`, then build
`frame_scan_bridge`. Frozen-source identity remains explicit while Ikea's
interface migration is in flight. The findings preserve each measured source cut.
`worker.sh` installs pinned actual Polars, recovers the existing input artifact,
copies the exact shared image before testing, and checks its hash afterwards.
The first real-input sweep may not supply all three cache-size regimes for every
column. The observations must say which intervals exist; repeated large work is
never labelled cache-hot merely because it repeats.
