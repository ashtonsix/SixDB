# Small source-level follow-ups (not implemented)

Do not ship assembler rewriting or encode current register names. Keep the ordinary permutation expression/control and compare an explicitly named source diagnostic on the complete current owner/caller. The successful binary intervention establishes that it is worth solving this lowering, not that an arbitrary C++ spelling reliably fixes it.

1. Materialize the count with a full definition in a small x86/BMI2 masking helper, then use the existing intrinsic. For K<64, an experimental body can use `unsigned count; asm("movl %1, %0" : "=r"(count) : "i"(K)); return _bzhi_u64(x, count);`. This output is opaque to optimization but its instruction necessarily defines the entire32-bit register, zeroing the high half. It can be hoisted if the compiler permits. Final callers must prove that no later low-byte copy reintroduces a carried dependency. Crucially, the opaque count may prevent folding a producer's key-domain mask into the seeded split mask, so extra masks and register/hoisting costs must be charged. This is a candidate for a source experiment, not instruction-parity evidence and not a proposed new public API.

2. A separate diagnostic can force full-word AND with a register-held mask (`asm("andq %1, %0" : "+r"(x) : "r"(mask(K)) : "cc")`). This removes BZHI count materialization entirely, at the price of a64-bit mask register and possibly a repeated producer mask. It is a different lowering control; do not combine its conclusion with the MOVL intervention. Audit full consumers, spills, hoisting, producer work and baseline symmetry. Do not narrow accepted key semantics to make the mask disappear.

The longer-lived solution may be an improved compiler lowering/cost choice for this partial-register case. A reduced compiler report can carry the minimal modeled trace and this complete-consumer receipt. A proposed compiler flag or backend change must affect all comparison arms consistently and be tested on the actual supported compiler/architectures. Merely changing a C++ variable to unsigned, using the BZHI intrinsic, or inserting an empty asm input does not guarantee full count materialization; final assembly remains the test.

No source helper has been compiled or timed by this follow-up, and none has been added to live code. The parent owns any subsequent implementation decision. Keep source changes small and local to word masking, with current all-width/kind complete consumers and ordinary baselines from the first measurement; do not open another bucket-layout sweep to validate this compiler issue.
