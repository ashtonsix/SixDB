# Settled Frame consumer port

This isolated six-file port exercises the current Ikea boundary against the
settled Frame lifecycle cohort. It preserves Frame's encoded bodies, parent
counts, numeric kernel interfaces and native controls. Live Frame sources and
historical controls are untouched. The seven selected checks and complete phase
program pass on native Graviton4 NEON and Zen5 AVX2/AVX-512, before and after.
This bounded source epoch is qualified; this receipt makes no runtime speed or
live Frame graduation claim.

The starting point is the qualified [warm lifecycle cohort](../../../../ikea-frame/lifecycle/ZEN5.md),
with its [source recovery](../../../../ikea-frame/lifecycle/evidence/native-zen5/REPRODUCE.md).
Its source archive is `a525096b5b8f323e83439f08039c33c896ffe6801375f3e0264c856b0e131e48`,
Frame core `3c3b5824`, Ikea `2ce62539`. Both comparison arms use this same Frame,
Orbital and control tree. The after arm changes Ikea and the six boundary files
in [migration.patch](migration.patch); it does not import the later point,
fused or predicate programs. [source.json](source.json) records the exact after
Ikea cut, changed-file hashes and helper hashes. Qualification retains this exact
provisional cut. The later R3 inline-visitor candidate has a separate object
reproof below; the reopened control/handle research does not relabel either
source epoch as a final freeze.

The [owner-program findings](../../../../ikea-frame/lifecycle/PROGRAM-COSTS.md)
require preserving native alternatives, NULL policy, selected work, retained
readers and the distinction between instrumentation and useful execution.
This port changes none of those choices. The stronger native scans and losing
compressed cases remain controls.

## Boundary migration

| Captured use | Current use | Contract retained |
| --- | --- | --- |
| `decoder<U>`, `bind_decoder<U>` | `erased_reader<U>`, `bind_reader<U>` | Explicit output type and parent logical count; dense bindings copy the admitted pointer/count proof and borrow the bytes. |
| `format<K>`, numeric-byte views | `layout<K>`, `view<L>` and explicit byte bridges | Same Local tiles and exact final-tile extent. Frame's private numeric-u8 storage and catalogue signatures remain unchanged. |
| `composition::describe` and physical filters | `author::expression` and expression filters | Original row coordinates, packet grants and masks; named sources survive their authored operation. |
| `bind_mutation`, construction capacity | `bind_writer`, `effect_capacity_initialize` | Named view and writer survive erased initialization; all inputs are admitted before stores. |
| Source-write journal records | Flat `journal::entry` records | Actual named source plus plane/offset/size; private construction keeps its original effects policy. |
| Private `set_unchecked` | `author::store_unchecked` | Initialized preserving bytes and complete owner exclusion; raw leaves emit no effects or summaries. |

No persisted child description is added. Frame's 16-byte descriptor, 24-byte
part dictionary record, explicit run/exception/dictionary counts, 256-row
coordinates and immutable interpretation remain parent facts. The runtime
byte-span conversions preserve their original extents. Explicit `<U>` binding
keeps the old output type rather than introducing a narrower arithmetic type.

The actual Orbital construction witness already disables address-bound retained
readers before copying encoded bodies into caller-owned storage. Subsequent
operations borrow those bodies with the parent's descriptor, grant, count and
dictionary edition. The port retains that policy; renaming the reader does not
put transient bindings into published material.

This is a bounded port of the settled cohort, not an update of every current
Frame entry. Later live Frame work must carry these boundary changes forward
into its own source epoch rather than replace its algorithms with this capture.

## Emitted code

[codegen-summary.json](codegen-summary.json) records literal object comparisons
with pinned Clang 21.1.8, O3, explicit ISA/tuning and automatic vectorisation.
API/type role names and source roots are the documented correspondence; machine
bytes, relocation offsets/targets/addends and data remain literal. ABI-distinct
Itanium constructor/destructor entries are retained even when they demangle alike.

The remaining 388-byte material function is checked Intervals range traversal
used by Frame's masked code count. Only the immediate operands at offsets
`0x10` and `0x1c` change from 5 to 7: old coordinate `error::rank` becomes
`error::range`. The function retains the same 97 AArch64 instructions, branch
structure, memory accesses and frame behaviour; every other byte and relocation
matches. The enum difference is retained in the receipt. Equal instruction shape
is evidence about emitted work, not a hardware timing result or a linked-placement
claim.

Packing is a real setup-code change, so it is recorded separately rather than
called equivalent. Both arms emit 473 functions; their aggregate function bytes
fall from 265,392 to 263,356, with 19,961 constant bytes in each. The outer
84-byte `pack` function matches exactly. Its width dispatcher shrinks from
31,732 to 30,328 bytes and reserves 256 rather than 352 stack bytes. Both
dispatchers contain 309 static call instructions; this is not the dynamic call
count of one packing operation.

At width 13, the checked writer falls from 114 to 103 AArch64 instructions and
its frame from 112 to 16 bytes. The raw initializer grows from 228 to 235
instructions and from 80 to 176 frame bytes: the 96-byte local metadata copy
moves into that helper so effects retain the actual named source identity.
The combined writer/helper frame remains 192 bytes. The vector-store loop
retains its instructions with two new alignment NOPs; the scalar tail issues
the same stores under a renamed count register. These observations establish
neither a complete encoding speed gain nor a linked-placement result.

The raw packing correspondence has 148 exact entries in a 699-name union,
including private coverage-signature changes and renamed mangled constant
labels. The receipt retains the unmatched entries and actual emitted sizes;
it does not treat unmatched functions as zero-cost removals.

The later R3 candidate adds `always_inline` to SeriesPack's point/region write
visitors. The separate [dependency proof](r3-dependency-proof.json) rebuilds the
three affected NEON objects against only that header change; phase-plane has no
changed dependency. Encoding material and phase material remain wholly exact.
Packing retains every function size, constant, relocation and unwind record.
Forty scalar-tail bodies change temporary GPR allocation, retaining their
instruction sequence and count. Thirty-six have one consistent register
permutation over the affected span; the four byte-width cases return to the
same destination register when their equal address expressions merge. Literal
byte mismatches remain recorded. This is an R3 emitted-code check, not a new
native qualification or a timing result. The
[two-attribute patch](r3-mutation-attributes.patch) preserves its exact input.

## Checks and reproduction

The selected executables are `frame_encoding_borrowed_check`,
`frame_encoding_masked_access_check`, `frame_encoding_null_check`,
`frame_phase_material_check`, `frame_phase_plane_check`,
`frame_phase_repair_check` and `frame_phase_batch_check`, together with the
complete `frame_phase_measure` program. The runner uses the existing four
8192-row input slices and their hashes from the captured `native-inputs.json`.
Borrowed checks retain checkpoint/dictionary choices and delta exceptions;
owner verification retains original coordinates, NULL/presence, selected blocks,
old readers and genuine successor publication. Existing `--check-*` programs
also run; their elapsed times are not interpreted as measurements.

The source-only worker payload contains both arms, `run-native.sh`, independent
qualification commands and a per-file manifest. The controller captures it
through the repository's managed source-capture mechanism. On each native
profile the runner configures the captured CMake projects, builds only the
selected targets, records actual Ikea dependencies from Ninja's consumed compiler
depfiles and saves the complete phase disassembly plus selected object records.
Those dependencies must match the final Ikea cut or the impacted consumers must
be rebuilt. Full paired trees, logs and assembly stay in ignored storage or the
worker archive; this directory keeps the reviewable patch and compact findings.

[native.json](native.json) independently checks both collected source archives
against their 10,601 member hashes, the 3,470/3,482 paired source files, all 96
helper hashes and all four input hashes. Each of the six native arms completed
the exact 82 requested commands with eight executable hashes and assertions
enabled. The 19,200 owner verification records all report `verification_run=1`.
Every non-time owner field matches before/after; the other 78 command logs per
arm match byte for byte. Qualification clocks are retained only as raw fields,
with no performance comparison inferred.

Full results and source recovery are retained in the
[Graviton artifact](native-neon-artifact.json) and
[Zen5 artifact](native-zen5-artifact.json). Their `source.tar.gz` is the same
managed capture, SHA
`4ffdadf7a993371c922cb4975f3bb9cac2c0fba201060280ac7dcf1d868213f1`,
which contains the paired payload under `frame-port/`. Recover it through the
repository's existing artifact helper and retain `source-manifest.json` beside
it. The source archive's repository entry script is
`workbench/spikes/ikea-composition/cohesion-v2-frame.sh`.

From the recovered source payload on Linux, with the pinned toolchain and an
allowed CPU (8 below), the complete qualification command is:

```sh
python3 verify.py
SIXDB_RESULTS="$(pwd)/results" SIXDB_CPU=8 SIXDB_BUILD_JOBS=6 bash run-native.sh
```

The runner selects the host's native profiles. To repeat the smaller object
comparison on a NEON host without running a timing workload:

```sh
taskset -c 8 python3 codegen.py --source phase-plane --profile neon-v2
```

Use `avx2-zen5` or `avx512-zen5` on the corresponding x86 host. Cross compilation
requires the matching installed GCC sysroot. Keep the source and helper manifest
with the outputs; a changed included Ikea file invalidates that object's earlier
source proof even if its `.cpp` is unchanged.
