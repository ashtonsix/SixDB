# Frame description, binding and owner composition

This is the phase-3 owner-side experiment for checklist A1/A2/A4/A6/A10,
A7–A9/B8/B9 and the owner account of B12. It uses the **shared**
[stage implementation](../proto/frame.h); there is no second encoding tree.
It is research, not a promoted `ikea::frame` interface.

## Consolidated boundary

The owner investigation is closed for feature expansion. The candidate covers
immutable non-null UInt64/H0 pack, bound/pack and both interval-root forms;
checked sparse section binding; and basic single-stream group afterimages.
The canonical graph also names deliberately refused extension shapes. The
material and histories are a concrete Orbital integration example, with owner
identity, retention and publication kept outside Frame's encoding contract.
For extraction, keep Frame's portable program/image/binding types independent
of Orbital ObjectStore and selection types. The concrete material remains a
maintained example and conformance fixture. The internal stage-author protocol
uses the shared logical/coordinate/effect vocabulary; a live C++ stage tree
does not define stored interpretation. The prototype's one-part admission bound
must remain explicit rather than become an accidental whole-column limit.

The [qualification account](EVIDENCE.md) retains the current source epochs,
counterexamples and completed preparation experiment. Current mutable-owner
throughput against a strong native owner, in-place lock projection and a
retained asynchronous preparation protocol remain outside the established
surface. Append, conversion and interval mutation use caller-driven full
rebuilds. These limits define the initial integration discussion; new performance
and encoding studies stay deferred during consolidation.

The earlier [end-to-end prototype](../proto/e2e.cpp) established retained
group Parts and exact old readers, but attached every group for each write
and kept interpretation in the driver. Its 9–17 µs draft/apply/emit cost was
mostly owner work. Phase 1's
[lifecycle account](../../frame-phase-1/lifecycle/PROGRAM-COSTS.md) also showed
that a logical fold grain does not imply independently reclaimable backing.
This experiment retains the existing group images, binds only admitted
groups, and gives their interpretation real lifetime ownership. Historical
timings do not establish this candidate's performance.

## Five different descriptions

| Description | Contents and lifetime |
| --- | --- |
| Logical contract | Ordered non-null UInt64 rows; exact unsigned 128-bit SUM, UInt64 COUNT; empty SUM/COUNT zero. Signed, floating, NULL and alternate orderings are not admitted here. |
| Fitting policy | Exception penalty/cap and reserved slack; supplied when constructing or rebuilding. Changing policy cannot reinterpret an existing image. |
| Actual representation | Immutable canonical pipeline bytes, logical row extent/schema identity, physical `part_extents` and the stream manifest. Retained by the material, not a transient builder. Per-block fitted bases/widths and exception membership are data in its sections. |
| Bound execution | Reader/stage objects and borrowed image addresses with explicit availability. An old binding remains valid under its retained immutable basis; it cannot be retargeted to a changed draft or interpretation. |
| Evidence and costs | Measured costs, fitted statistics and their validity/basis. They are neither decoding parameters nor zero when unknown. |

[description.h](description.h) provides a bounded, versioned description in
Ikea's existing five-byte envelope (`Fr`, version 1). Node identities and
ordered edges preserve sharing; child coordinates distinguish identity,
checkpoint, present-rank, record-field and run-ordinal relationships. Decode checks exact
length, parameters, topology and reachability before a binding is attempted.
This is an envelope for composition, not a replacement SeriesPack format.
Fr version 1 freezes the resolved geometry per remaining-payload width for its packing families;
a future SeriesPack preset recommendation cannot reinterpret old bytes:

| Fr/v1 packing family | Striped payload widths P=K−H | Other payload widths |
| --- | --- | --- |
| `compact` | None | Local |
| `bulk_x86` | 1–7, 12, 20 | Local |
| `bulk_arm` | 1–7, 10, 12, 14, 15, 20 | Local |

The currently executable Frame recipes use `H=0`; width K=0 then has no leaf
body. The description can also name H=8/H=16 as a leaf-interpretation
placeholder, independently of the packing family. Actual image width K must
satisfy H≤K, and geometry applies to P=K−H. A description alone cannot prove
that relationship. H0 descriptions retain their previous bytes; the former
reserved u16 now names heads, and every non-pack node still requires zero.
Older strict readers reject the new placeholder descriptions; unchanged H0
bytes do not imply forward compatibility with those descriptions.
The CPU-oriented names identify byte-law families, not the CPU on
which they must execute. The checked factory verifies compiled-family
availability and equality with the frozen mapping before passing a SeriesPack
preset to the shared backend; a changed recommendation refuses rather than
reinterprets the image. The compiled runtime leaf accepts resolved geometry.
The 256-row blocks, 16-block groups and current 65,536-root-row limit are experimental
admission bounds, stated independently of addresses and physical Part counts.

The executable subset is group-local `pack`, optionally under `bound`, and
an `intervals_sizes` or `intervals_relative_ends` root with separate basic
field/checkpoint children. It uses
the existing SeriesPack presets; an omitted compiled preset refuses before any
payload access. Runs, headed leaves, shared tuple records, rank maps, split nodes and
nested interval programs can describe an extension's **shape**, but the checked
factory refuses their execution until the corresponding stage contract exists.
Shape validation is distinct from executable byte-law and operation support.

### Required placeholder witnesses

The canonical `runs` node has two ordered numeric children: run sizes minus
one, then run values. Both edges use this parent's `run_ordinal` domain, with
the same data-dependent cardinality M. Parameter 0 fixes the current semantic
scope: runs terminate at each `description.block_rows` boundary. M and the
parent-block→child-row map belong to image interpretation, not the pipeline
description. No Part assignment, image section or global-run mode is implied.

The existing shared in-memory `runs` stage supplies the reference witness. For
257 equal values, its two children have two rows, sizes-minus-one `[255,0]`
and equal run values. Alternating input has 257 singleton runs and zero sizes
minus one. Exact reads, points across rows 255/256 and SUM preserve the original
values in both cases. The canonical graph round-trips, but the checked owner
factory refuses it before touching an inaccessible payload: RLE image import,
publication, write and operation-binding support remain research.

The leading-plane witness uses existing SeriesPack layouts directly at
K/H=12/8, 20/8, 20/16 and 32/16, with 257 rows and a partial final tile. It writes
and reads actual body/head planes, checks the leading bytes against each
layout's K, and matches the remaining-payload geometry to the canonical family.
This distinguishes a fitted-width head from a fixed logical high-bit split.
Canonical H8/H16 leaves round-trip, while plain and bound-headed owner recipes
refuse before payload access. This proves the existing leaf's physical seam;
it establishes no headed Frame group-image placement, dependency or execution
contract. Shared TuplePack record/field nodes remain shape placeholders too.

[manifest.h](manifest.h) retains each stream's node identity, actual row count
and group sections as `(owner Part, offset, extent)`. `part_extents` bounds
physical backings; section locations use original material Part ordinals,
including after selected-Part projection. The manifest is image metadata, not
another persisted stage graph: the program owns G and child-coordinate laws,
and local prototype roles map explicitly to its node IDs. Validation checks
the complete stream set, row/group counts, Part bounds and non-overlap without
reading payload. Section byte validity and owner read grants remain separate.
A different row domain
does not require a different Part: disjoint sections may co-pack, while the
first interval recipe places checkpoint sections separately. For G16, each
parent group needs 256 checkpoints, while the default checkpoint group can
contain 4096. That larger copy/retention grain is a recipe cost, not hidden work
or a mandatory layout for future children. For R=4,367/G64, root group 1 uses
checkpoint rows 64–68 in checkpoint group 0; a root group number is not a
checkpoint group number.

## Admission and partial binding

[group_image.cpp](group_image.cpp) validates Frame's parent composition before
the prototype's trusted `attach`. It checks block rows/widths, contiguous
exception ranges, sorted unique positions, array membership/slots, widths,
row counts, exact leaf extents and total input length. It also uses Ikea's
actual compiled reader to prove the zero residual at every exception and
the absence of logical base-plus-field overflow. Leaf validity alone does
not prove either condition. Validation is a cold admission cost, not a
per-query charge.

The existing headless group sections remain little-endian: bound's block
descriptors and reserved exception area, then pack's block descriptors and
width arrays. The immutable description identifies this composition law.
Inactive reserved slots and unused leaf padding do not carry logical values;
this prototype does not require logically equivalent data images to have one
unique byte string. Canonical **description** encoding is exact and independent
of those data bytes. The current trusted prototype operates on little-endian
hosts; a portable description does not grant a big-endian execution backend.

`binding::attach(description, rows, groups)` receives only the groups the
caller has acquired. An absent group has no address and no halo requirement.
Duplicate/out-of-range group identities or inconsistent images refuse.
`available_blocks()` reports what was attached. Every checked operation
rejects an unavailable requested block before entering a stage, rather than
silently reducing the request to available data or interpreting it as zero.
Range reads validate the entire request before writing output. Fine masks
use original-row coordinates and cannot select beyond a final partial block.

Selections express demanded work, not physical read authority. This first
recipe admits entire available section windows; it does not claim fine-mask
isolation within them. [stream_binding](stream_binding.h) validates complete
metadata before resolving addresses, and attaches only explicitly available
sections. A whole Part span is a placement bound; physical co-location grants
no other section. Its copied program, manifest and available-key set can
outlive the caller's transient metadata containers. Payload addresses and
read-isolated bytes remain borrowed from the owner's retained Scope/Parts.
There is no mutation or escaping point-plan API on this binding.

The stream binding checks each child in its own row domain. With complete
dependencies, ordinary decode proves stored last values and the soundness of
true monotone/exact flags before shortcut laws are used. For sizes, exact means
each adjacent logical difference fits signed64; it does not promise that every
relative prefix fits signed64. For relative ends, exact means each value's
offset from its region checkpoint fits signed64. A positive difference must be
strictly below 2^63; a negative magnitude may equal 2^63. False flags may
conservatively decline a law.

Every checkpoint row's logical child field must be the offset-binary encoding
of zero (2^63), including after bound/exception interpretation. Plain point and
decode routes ignore those fields, while the relative-ends SUM law includes
them. Therefore a successful decoded-value proof alone is insufficient: the
attacher proves this additional premise before a group becomes ready.
Available roots with missing checkpoint sections may attach structurally, but
payload-dependent queries refuse. A new binding can be formed after the owner
acquires the missing sections. Cached
per-group proofs keep repeated points allocation-free. These are validation
and binding costs, charged separately from a repeated query.

The stream facade exposes `get`, `read`, coarse `sum`/`count`/`filter`, fine
`sum_selected` and `select`. Coarse bits name original root blocks; fine bits
name original rows within each block. FILTER updates only requested coarse
slots, clears unused high bits in a final partial block, and preserves excluded
slots. SELECT gathers fine-selected values in original row order and returns
their count. It checks output capacity before writing and preserves output
beyond that count; shortage returns `binding_error::resources`. Range, mask,
availability and capacity refusals leave output unchanged. The caller proves
output disjoint from source, binding storage and input masks. Empty fine demand
needs no payload for selected SUM or SELECT, even with unavailable coarse blocks.

COUNT and FILTER can settle four predicates from the non-null UInt64 logical
contract alone: `>=0` and `<=UINT64_MAX` select every live requested row; `<0`
and `>UINT64_MAX` select none. Comparison and coarse-domain checks still run
first. These operations need no payload or fitted evidence and work with every
section unavailable. Other predicates require the admitted immutable closure.
`required(row_ranges)` reports conservative point/read dependencies; it is not
a minimum-acquisition claim for every operation.

## One group, one private draft, ordered commands

`prepare_group` is an **afterimage** route:

1. Admit source readability, row/group coordinates, pipeline and image.
2. Admit source-copy size, command count and reusable journal capacity; allocate
   private preparation resources. Allocation failure can still refuse privately.
3. Copy and attach the touched group once, keeping original part coordinates.
4. Execute commands in order. Classify from the private interpretation, declare
   private apply effects, check journal capacity, then apply; exhaustion can
   rebuild only this group. It never falls back to reading a whole part.
5. Resolve issued private stores and check that declarations cover them.
6. Derive exact logical SUM/MIN/MAX, emit once, validate the final image and
   enforce the output-size budget.
7. The owner captures the fresh group together with certified retained sources
   for untouched groups, and publishes data and matching derived state.

Refusal drops the private candidate. The source image and published state are
unchanged, including when a later ordered command fails after earlier private
commands succeeded. No raw pointer into preparation workspace escapes.

The budget bounds copying, command count, peak reusable **per-command** journal
capacity and output size. It does not yet prove a hard bound on all allocator
overhead. `issued_bytes` and `records` count private apply stores cumulatively;
rebuild and emission construction stores are not in those counters.
`copied_bytes` and `new_bytes` report source copying and the final image. The
history accounts independently retained bytes separately. These counters must
not be labelled physical memory-bus traffic.

This distinction is necessary: current `bound::attach` copies descriptors
and exception vectors into binding workspace, while the leaf borrows draft
bytes. Granting an external image is not granting that private workspace.
The published physical effect here is replacement of the finished group;
the journal describes private computation. This fixture does not establish
an in-place publication contract or a lock manager. In-place binding still
needs explicit descriptor placement/workspace and owner-store admission.

## Interpretation and publication lifetimes

[material.h](material.h) supplies a concrete compile-once public Orbital
material. Immutable interpretation is retained independently of payload;
physical Parts retain their immutable interpretation and own backing without
keeping sibling payloads. A logical read outside a Scope must retain its whole
required section closure, including separately placed checkpoints; a lone root
Part does not silently pin every dependency. Missing dependencies refuse. The
resource outlives every owner, Scope and escaped Part. The material's identity/resource checks are necessary admission, not a
proof of logical equivalence.

The original Scope/basis remains alive through Frame preparation and Orbital
packet preparation. An unrelated publication during Frame preparation makes
that basis stale: the owner must reject or explicitly revalidate and retry.
Orbital admits only one accepted packet at once, so there is no invented
competing-publication race between successful `Store::prepare` and `install`.

`same_material(a,b)` compares two live protected material bases: resource,
the complete immutable interpretation (including stream placement), Part
identities/extents and selected addresses. It reads no payload. Equal pipeline
bytes, row counts and addresses alone are insufficient: a valid manifest can
swap equal-sized groups and change logical row values without moving bytes.
The helper detects that remap, but neither proves logical equivalence nor
validates the Store cut, another participant or a read grant. Absence provides
no basis proof, even against another absent selection. The retry fixture names
a fresh Scope, compares the actual source material, then reruns preparation
against that basis; it never silently substitutes a new Scope at publication.

A SET that exhausts slack and rebuilds is still a logical change: publish the
next logical version and its exact contribution. A pure equivalent conversion
is separately proved from logical values and uses Orbital's same-version
`adopt`, with zero logical contribution. Copying, destination sizing and
policy choice remain owner responsibilities. Old readers retain their own
row extent and pipeline through append and conversion.

## Checks and scorecard

`frame3_owner_description_check` independently checks canonical bytes,
malformed descriptions, shared identity and placeholder refusal.
`frame3_owner_material_check` checks interpretation/payload/resource lifetime,
escaping selected Parts, append, source reuse and adoption compatibility.
Group-image and complete-history checks extend these to real stage images.
`frame3_owner_manifest_check` tests metadata-only dependency/placement admission;
`frame3_owner_stream_binding_check` and `frame3_owner_stream_history_check`
exercise real G16/G64 images of both interval forms, constant/zero-body cases,
partial tails, guarded missing dependencies and atomic two-section replacement
with old readers. Pure same-version conversions run in both directions between
sizes and relative ends: rebuilt target images are independently checked before
adoption, while retained source readers keep their own interpretation and rows.
The facade tests also cover FILTER/SELECT output guarantees, payload-free
domain settles and metadata-only basis changes. The checked relative-owner
baseline passes frozen normal and ASan/UBSan checks with the compiled runtime
leaf. The new RLE/head placeholder extension also passes matching normal and
owner/runtime/Orbital ASan/UBSan checks. The linked SeriesPack archive remains
uninstrumented and is covered by hardware guards.
See [evidence status](EVIDENCE.md) for exact scopes; interval writes here use
full rebuilds for correctness, not a claimed optimized setter.

Configure the existing spike with `-DSIXDB_SPIKES=frame-phase-3`, then build
the needed `frame3_owner_*_check` targets. Use the pinned Linux toolchain;
prefix Linux commands with `orb -m ubuntu` in the macOS workspace.
The [qualified controls](../controls/README.md) and
[scorecard](../controls/SCORECARD.md) distinguish whole operations, preparation,
residence conditioning, retained bytes and remaining unmeasured cells.
